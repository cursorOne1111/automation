# 后端商品与订单接口测试计划

基础环境：本地 demo `/api/v1`；每用例独立租户，管理员与只读Token各自登录；最终清理租户与全部会话。
契约与数据基线见 [后端指南](../docs/BACKEND-API.md)。计划中的参数组展开为独立用例。

| ID | 场景与步骤 | 预期及副作用 |
|---|---|---|
| BE-AUTH-001 | 只读账号登录并查询 | Token契约正确，角色reader，查询200 |
| BE-AUTH-002 | 缺失/假Token/Basic/错误Bearer，共4组 | 401，统一错误契约 |
| BE-AUTH-003 | 错误密码/未知用户，共2组 | 401，不返回密码 |
| BE-AUTH-004 | reader创建和清理 | 403，订单和库存不变 |
| BE-AUTH-005 | Token加其他租户头 | 403，不能越权 |
| BE-AUTH-006 | 注销后查询 | 204无响应体，然后401 |
| BE-AUTH-007 | 缺少租户头 | 400 |
| BE-AUTH-008 | 登录字段缺失 | 422 |
| BE-AUTH-009 | reader取消订单 | 403，订单状态与库存不变 |
| BE-AUTH-010 | 清理后访问、重新登录 | 全部旧Token失效，初始库存恢复，订单清空 |
| BE-ORDER-001 | 创建2件→查询→取消→再查询 | 金额2598分、库存5→3→5、版本1→2、状态持久化 |
| BE-ORDER-002 | 购买6件超过库存5 | 409，无订单，库存不变 |
| BE-ORDER-003 | 同键同参数重复提交 | 201后200，同ID、同原始响应，扣库存一次 |
| BE-ORDER-004 | 同键不同数量 | 409，原订单与库存不变 |
| BE-ORDER-005 | 错版本取消→正确版本→重复取消 | 版本及状态409，库存仅回补一次 |
| BE-ORDER-006 | 其他租户查询已知订单ID | 404，列表隔离、库存隔离 |
| BE-ORDER-007 | 不存在商品或订单 | 404，不产生订单 |
| BE-ORDER-008 | 库存5，8次并发下单 | 成功5、冲突3，库存守恒 |
| BE-ORDER-009 | 相同键6次并发 | 创建1、重放5，只有1个订单 |
| BE-ORDER-010 | 相同版本2次并发取消 | 成功1、冲突1，只回补一次 |
| BE-INPUT-001 | 两页查询与越界空页 | 分页契约、总数、唯一商品、no-store |
| BE-INPUT-002 | 非法分页5组 | 422 |
| BE-INPUT-003 | 数量0/负数/小数/字符串/null/101，共6组 | 422，无订单、库存不变 |
| BE-INPUT-004 | null/数组/字符串/缺字段/伪造金额，共5组 | 422，无订单 |
| BE-INPUT-005 | 缺少幂等键 | 400，无订单 |
| BE-INPUT-006 | 原始字节发送畸形JSON | 400，无订单，服务继续可用 |
| BE-INPUT-007 | text/plain请求体 | 415，无订单 |
| BE-INPUT-008 | 超16KiB请求体 | 413，无订单 |
| BE-INPUT-009 | PUT、未知路由、非法订单ID | 405含Allow、404、400 |
| BE-INPUT-010 | 非法版本4组 | 422，状态和库存不变 |

实际展开为50个后端用例：鉴权14、订单10、输入与协议26。
待扩展：Token自然过期、真实数据库约束、事务回滚、服务依赖超时、分布式幂等、限流与性能。当前没有验证这些能力。
